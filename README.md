# Практическая работа: паттерн «Итератор» (Iterator)
Дисциплина: Разработка программных модулей
Язык программирования: C#
Время выполнения: 1 пара (90 минут)
Тема: Реализация поведенческого паттерна проектирования «Итератор».

## 1. Цель работы
Научиться применять паттерн «Итератор» для последовательного перебора элементов коллекции без раскрытия её внутреннего устройства. Закрепить навыки работы с интерфейсами IEnumerable<T> и IEnumerator<T>. Научиться работать с GitHub.
## 2. Постановка задачи
Необходимо разработать консольное приложение «Каталог библиотеки», которое позволяет хранить информацию о книгах и последовательно просматривать их с помощью собственного итератора.
Библиотека содержит коллекцию книг, однако пользователь приложения не должен обращаться к её элементам напрямую по индексам. Для просмотра книг необходимо реализовать отдельный класс итератора, который будет отвечать за перемещение по коллекции.
В ходе работы необходимо создать репозиторий публичного доступа, и от ветки Main образовать Pull Request, в котором нужно последовательно вести серию Commits.
## 3. Технические требования
### Задание 1. Создание модели книги
Создайте класс Book, описывающий отдельную книгу.
Класс должен содержать следующие свойства:
Title — название книги.
Author — автор книги.
Year — год издания. 
Предусмотрите конструктор для инициализации свойств и метод ToString() для удобного отображения информации о книге.
### Задание 2. Реализация коллекции
Создайте класс BookCollection, реализующий интерфейс IEnumerable<Book>.
Коллекция должна обеспечивать следующие возможности:
Хранение книг во внутреннем списке List<Book>.
Добавление новых книг с помощью метода AddBook().
Получение количества книг.
Создание собственного итератора с помощью метода GetEnumerator().
Внутренняя коллекция не должна быть доступна для непосредственного изменения извне.
### Задание 3. Создание итератора
Разработайте класс BookIterator, реализующий интерфейс IEnumerator<Book>.
Итератор должен хранить ссылку на коллекцию и текущую позицию перебора.
Реализуйте следующие элементы интерфейса:
 - MoveNext() — перемещает итератор к следующей книге. Возвращает true, если переход выполнен успешно, и false, если коллекция закончилась.
 - Current — возвращает книгу, находящуюся на текущей позиции.
 - Reset() — возвращает итератор в начальное состояние, перед первым элементом.
 - Dispose() — освобождает используемые ресурсы при необходимости.
 
Обратите внимание, что при создании итератора текущая позиция должна находиться перед первым элементом коллекции.
### Задание 4. Демонстрация работы
В главном методе программы выполните следующие действия:
- Создайте экземпляр BookCollection.
- Добавьте в библиотеку не менее пяти книг.
- Выведите все книги с помощью цикла foreach.
- Получите итератор с помощью GetEnumerator() и вручную переберите книги, используя MoveNext() и Current.
- Продемонстрируйте работу метода Reset(), повторно выведя коллекцию с начала.
- Создайте два независимых итератора и убедитесь, что перемещение одного не влияет на позицию другого.
- Продемонстрируйте замёрженый пул реквест.
- Продемонстрируйте историю коммитов в этом пул реквесте.

### 6. Ограничения
- Запрещается использовать yield return для реализации итератора.
- Запрещается возвращать готовый итератор внутреннего списка через List<T>.GetEnumerator().
- Логика перемещения по коллекции должна находиться в классе BookIterator.
- Для перебора коллекции в главном методе необходимо использовать созданный итератор, а не прямой доступ к элементам списка по индексам.
- Запрещено вливать в мейн ветку напрямую, минуя этап с Pull Request
- Запрещено делать 1 коммит, который реалезует все 3 этапа задания.
### 7. Дополнительное задание (*)

- Добавьте в BookCollection метод GetReverseEnumerator(), возвращающий обратный итератор.
- Продемонстрируйте работу обоих способов перебора, не изменяя порядок хранения книг в коллекции.
### 8. Критерии успешного выполнения
- Работа считается выполненной, если:
- Коллекция поддерживает добавление и хранение книг.
- Собственный итератор корректно реализует интерфейс IEnumerator<Book>.
- Перебор через foreach работает без ошибок.
- Методы MoveNext(), Current и Reset() выполняют свои функции.
- Несколько экземпляров итератора могут независимо перемещаться по одной коллекции.
- Хронология работы чётко виднеется в истории коммитов
- Постепенная разработка ведётся в пределах вашего пул реквеста
- Пул реквест успешно замёржен.
- Программа не нарушает установленные ограничения.
- Результат работы: готовое консольное приложение, демонстрирующее использование паттерна «Итератор» на примере собственного каталога книг, с понятной историей разработки в Git Hub.
